* 仓库结构
- 任何不以 "." 或 "_" 开头的顶层文件夹，视为一个独立的子项目。
- 不在任何子项目中的顶层代码，视为胶水代码。胶水代码默认许可（GPLv3+）发布。

* 子项目许可的声明规则
1. 若子项目的顶层文件夹内包含文件名为 =LICENSE*= 的文件（不区分大小写），则子项
   目的许可以该文件为准。该文件与根许可说明冲突时，以子项目文件为准。
2. 若子项目是维护者原创或拥有完全版权，且不包含 =LICENSE*= 文件，则该子项目以默
   认许可发布。
3. 若一个子项目不符合第二条规则，且没有上述许可声明文件，则：
   - 该子项目可能缺乏有效许可，默认保留所有权利。
   - 本仓库不会自动为其添加任何许可。
   - 此时应认为该子项目“许可不明”，请勿使用或分发，并联系原始版权持有人。
   - 这应该是一个错误，请尽快联系维护者删除。
4. 所有分叉/引入的第三方子项目，均须完整保留其原始的 LICENSE、COPYING、NOTICE 及
   版权声明文件，不得删除或修改其内容。若子项目顶层缺乏符合第一条模式的许可文件，
   可采取以下任一方式使其存在唯一一个符合第一条规则的文件，且该文件内容须准确反
   映原许可：
   - 创建一个在说明中明确指向真实的原始许可文件的说明文件（例如包含类似如下文本
     的org文件）:
     #+begin_src org
       This project follows [[file:path/to/LICENSE][LICENSE]].
     #+end_src
   - 将 COPYING 等文件重命名为 LICENSE（或任何符合第一条规则的文件名）。
   - 创建一个内容与原始许可文件等效的 LICENSE 文件（例如复制全文）。
   - 创建指向原始许可文件的软链接 LICENSE。
   若子项目已包含符合第一条模式的许可文件，则无需额外操作。
